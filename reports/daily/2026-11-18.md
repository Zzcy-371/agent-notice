## GitHub projects

### [TradingAgents：基于 Multi-Agent LLM 的金融交易框架](https://github.com/TauricResearch/TradingAgents)
- 利用 multi-agent 协作架构，让不同的 LLM 智能体分别承担分析师、研究员、交易员与风险管理等角色，协同完成金融交易决策。
- 通过 tool calling 接入行情数据、财务指标与新闻等外部工具，并结合 RAG 检索增强生成，为智能体提供可溯源的信息支撑。
- 提供可扩展的 MCP 式工具与数据接口设计，便于集成新数据源与策略模块，从而支持端到端的交易研究与回测流程。


## Research and engineering

### [编码智能体究竟需要什么上下文](https://arxiv.org/abs/2607.09691)
- 论文探讨 coding agent 需要哪些上下文，涵盖 MCP、RAG、tool calling 与 multi-agent 等机制。
- 文章发布在 arXiv，并在 Hacker News 上引发讨论，当前有 1 分和 1 条评论。
- 核心问题是：在有限的上下文窗口内，如何筛选并组织对编码任务真正有用的信息。

### [一个用于对本地 LLM 服务器速度进行爬山优化的 agent skill](https://github.com/sybil-solutions/inference-optimisation-skil)
- 介绍一个 agent skill，通过迭代爬山方式调优本地 LLM 推理服务器的速度配置
- 该 skill 适用于需要持续压测和调参的本地推理场景，可与 MCP、tool calling 等机制配合使用
- 仓库附带实现与使用说明，HN 讨论区当前关注度较低，暂无评论

### [Purpose-Governed Agents：谁审查 AI agent 如何描述自己的提案](https://zenodo.org/records/23778866)
- 文章探讨当 AI agent 通过 tool calling 或 MCP 接口提交自身提案时，应由谁审查其自我描述的真实性与一致性。
- 提出需要治理机制来约束 agent 对自身意图的表述，避免在 RAG 与 multi-agent 协作场景中产生误导性自述。
- 配套讨论聚焦该治理框架的可行性与审查责任归属问题。
