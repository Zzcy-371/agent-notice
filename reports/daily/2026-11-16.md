## GitHub projects

### [codex](https://github.com/openai/codex)
- 一个轻量级的终端编码 agent，直接在命令行中运行并协助完成编码任务
- 支持 tool calling，可调用外部工具扩展能力，并结合 RAG 检索上下文提升代码理解
- 可用于构建 multi-agent 工作流，也可作为 MCP 生态中的轻量编码组件

### [Agent-Reach：让你的 AI agent 看见整个互联网](https://github.com/Panniantong/Agent-Reach)
- 一条 CLI 统一接入 Twitter、Reddit、YouTube、GitHub、Bilibili、小红书等平台的读取与搜索能力，零 API 费用，可直接作为 tool calling 能力提供给 agent。
- 为 RAG 与 multi-agent 流程补充实时、跨平台的互联网信息源，让 agent 不再依赖封闭的单一数据接口。
- 通过 MCP 方式把多平台检索能力暴露给任意 AI agent，减少自建爬虫与 API 集成的工程成本。

### [LLM 智能体何时该遗忘？查询关键型解析器错误下的记忆过滤](https://arxiv.org/abs/2611.17338)
- 新研究表明，LLM 记忆系统若采用硬过滤删除被判定为过时的事实，在 resolver 错误删除查询关键事实时会降低下游准确率：敏感度干预实验中，完美解析下硬丢弃带来 +0.186 至 +0.230 的增益，而最低可靠性下则转为 -0.176 至 -0.181 的损失。
- 配对靶向干预显示，false-drop 造成的性能退化显著大于 false-keep；即便基线不执行删除，只要错误标签误导生成，仍可能失败。这说明简单绕过删除并不足够，RAG 与 tool calling 中的记忆管理需关注标签噪声。
- 作者建议将删除视为代价敏感决策：在匹配数据上验证查询关键型 false-drop 风险，否则默认采用无标签保留；在冻结的 102/102 划分上，部署匹配门控达到 0.655 准确率，介于始终硬丢弃（0.641）与测试信息 oracle 选择（0.662）之间，而全局准确率交叉点仅是依赖金标签的模型与任务特定诊断，并非部署阈值。
