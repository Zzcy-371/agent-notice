## Research and engineering

### [为什么 agent swarms 规模越大，优化代码的能力越强](https://frontier.replit.com/throwing-headcount-at-the-problem)
- 文章探讨用“堆人力”的方式扩展 agent swarms，观察随规模增长在代码优化任务上的表现变化。
- 涉及 tool calling、RAG 与 multi-agent 协作等机制，分析规模扩张如何影响搜索与优化效率。
- 来自 Replit Frontier 的文章，HN 讨论帖附带原文与评论区链接。

### [重放 agent run 及其所需条件](https://github.com/chizy7/tether/blob/master/docs/REPLAY.md)
- 重放一次 agent run 需要精确记录模型输入、tool calling 的参数与返回，以及 MCP 等外部依赖的状态，否则无法忠实还原。
- RAG 检索结果与 multi-agent 之间的消息传递顺序必须在记录中固定下来，才能保证重放时行为一致。
- 该文档讨论了构建可重放 agent 系统的工程设计取舍，包括确定性边界与副作用处理。

### [Show HN：面向 AI 代码的 Git blame，精确到 agent session](https://keepplain.com/blame)
- 该工具把 Git blame 扩展到 AI 生成的代码，可追踪每行代码来自哪个 agent session。
- 核心思路是记录 agent session 的上下文，并与 RAG、tool calling 等生成过程关联，便于审计与回溯。
- 讨论涉及 multi-agent 场景下的责任归属，以及在 MCP 等协议下如何标准化这类溯源元数据。
