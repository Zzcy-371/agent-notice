## Research and engineering

### [Show HN：Sphinx – 在你 push 前考查你是否真的理解 AI agent 代码的 hook](https://sphinx-six-theta.vercel.app/)
- 这是一个 FOSS 项目，可接入你现有的 coding agent 工作流：每次 push 到生产环境时，它会弹出一份问卷，检查你是否理解自己正在推送的代码如何运作。
- 它的核心思路是把「由 AI 生成代码」变成「由人确认理解代码」，在流程上为 tool calling、多步推理这类不透明的 agent 行为加一道人工审查。
- 讨论区目前还没有评论，这也留下了悬念：这种 push 前问卷能否推广到 MCP、RAG、multi-agent 等更复杂的场景。

### [My AI agent caught most of our sites saying sent while no email left the server](https://iampneuma.com/the-function-returned-true)
- 文章讲述一个 AI agent 在 MCP 场景中发现多数站点在 SMTP 流程里报告发送成功，但邮件实际从未离开服务器。
- 问题根源是 tool calling 的返回值被误用：function 返回 true 并不代表投递成功，需要结合 RAG 检索日志与状态校验确认。
- 作者建议在 multi-agent 架构中加入独立的投递验证环节，避免依赖单一布尔返回值判断邮件是否发出。

### [将你的编码 agent 会话转化为私有 evals](https://github.com/ibragim-bad/evals-from-sessions)
- 该开源项目把 coding-agent 的历史会话转化为可复用的私有 evals，帮助开发者围绕真实任务轨迹构建评测集。
- 适用于 RAG、tool calling 与 multi-agent 等复杂工作流，可在本地复现并对比不同模型或配置的表现。
- 会话数据保留在私有环境中，便于团队针对 MCP 工具调用等场景做定制化回归测试与质量把关。
