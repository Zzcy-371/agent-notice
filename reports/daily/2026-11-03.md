## Research and engineering

### [Agent Memory 基准应衡量任务成功率，而非仅衡量检索效果](https://x.com/AgentMemoryL)
- 评测 Agent Memory 应以端到端 task success 为核心指标，retrieval 命中率只是中间信号，不能代表 agent 真正完成任务的能力。
- 在 MCP、RAG、tool calling 与 multi-agent 场景中，记忆的价值取决于能否支撑正确决策与行动，脱离任务上下文的检索分数容易产生误导。
- 建议基准设计同时记录任务完成率、跨会话记忆复用效果与失败归因，从而区分记忆质量与检索召回带来的增益。

### [Verify, Then Vote：多 Agent LLM 中纠正错误多数意见的新方法](https://github.com/grainulation/papers)
- 论文探讨 multi-agent LLM 系统在投票决策中如何识别并推翻错误的多数结论，强调先验证再投票的流程设计。
- 该方法可推广到 RAG、tool calling 与 MCP 等场景，用于降低多个 agent 一致犯错时的风险。
- 文章已发布在 GitHub 论文仓库，并在 Hacker News 上获得 3 分、暂无评论。

### [Show HN: MCPgraphy – 一个能学习你的 agent 的 MCP 工具何时有效的 proxy](https://github.com/hemanth1999k/mcpgraphy)
- MCPgraphy 作为 proxy 运行，可以观测并学习 agent 在调用 MCP 工具时的实际表现，判断哪些工具调用真正有效。
- 项目与 RAG、tool calling、multi-agent 等场景相关，目标是帮助开发者理解并优化 agent 的工具使用行为。
- 源码已发布在 GitHub，Hacker News 上提供了讨论链接，当前获得 1 分、暂无评论。

### [我们构建了一个使用你的纳税申报表的选民教育专家 Agent](https://serendb.com/caroline-hughes)
- 该系统将纳税申报数据接入选民教育场景，通过 MCP 与 tool calling 让 Agent 在受控权限下调用外部工具和私有数据。
- 实现中结合 RAG 检索政策与选举信息以提供可溯源回答，并用 multi-agent 架构分离数据访问、合规校验与对话生成职责。
- 文章强调隐私与权限边界设计，讨论敏感税务数据在教育类 Agent 中的最小化使用、审计与用户同意机制。
