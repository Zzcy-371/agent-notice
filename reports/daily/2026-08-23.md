## GitHub projects

### [agency-agents](https://github.com/msitarzewski/agency-agents)
- 基于MCP协议构建的多智能体系统，集成RAG知识库，支持动态tool calling，实现从前端开发到社区运营的全流程自动化协作。
- 每个agent具备独立人格与专业流程，通过multi-agent调度机制协同工作，可注入创意元素并进行现实校验，确保交付质量。
- 覆盖Reddit社区管理等场景，提供可复用的agent模板与工具链，助力快速搭建定制化AI代理团队。

### [browser-use](https://github.com/browser-use/browser-use)
- 通过 MCP 协议将浏览器能力暴露给 AI 代理，使代理能直接操控网页元素，实现自动化任务执行。
- 集成 RAG 技术，代理可实时检索网页内容并生成上下文相关响应，提升信息获取与处理效率。
- 支持 tool calling 机制及 multi-agent 协作，允许多个代理协同完成复杂浏览器操作，如表单填写、数据抓取等。

### [Show HN: A2G (Agent to Agent) Marketplace – Beta Test](https://www.a2gmarketplace.com)
- A2G 是面向智能体经济的商业层，通过一个 API 让买方智能体发现、雇佣并支付专业卖方智能体完成端到端的工作，流程涵盖 token → search → quote → authorize → confirm → hire。
- 该平台整合了 MCP、RAG 和 tool calling 等关键技术，支持多智能体协作，使智能体之间能够高效交互并执行复杂任务。
- 目前正在招募 Beta 测试者和反馈，开发者可通过 hello@a2gmarketplace.com 提交智能体列表或参与测试。

### [Ordinary agent tool calls can create shadow delegation](https://niyikiza.com/posts/agents-to-agents)
- 普通代理工具调用可能产生影子委派，即代理在未显式指定的情况下，通过工具调用间接触发其他代理执行任务。
- 在MCP（模型上下文协议）和RAG（检索增强生成）环境中，影子委派可能导致多代理系统出现意外的协作行为，增加系统的复杂性和不可预测性。
- 设计多代理系统时，需显式管理代理间的委派关系，避免依赖隐式工具调用，以确保tool calling的透明性和可控性。
