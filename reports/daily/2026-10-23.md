## Research and engineering

### [打招呼的代价：AI Agent 通信协议握手开销的实证研究](https://arxiv.org/abs/2610.30151)
- 首个按阶段分解的握手基准：在 50ms RTT 下，legacy MCP 握手需 3 次往返、230ms，A2A 仅需 1 次往返、61.0ms，说明往返次数主导握手成本。
- 当 LLM 读取对端元数据时，握手成本随能力清单规模增长（每项能力 24-107 tokens），200 项能力的对端会占用 200k 上下文窗口的 11%。
- MCP 2026 修订将握手从 3 次往返降至 2 次，并借助 era pinning 在热重连时降至 0 次，印证了所测成本；全套 harness、原始数据与分析已开源。

### [MCP 与 CLI：AI Agents 工具集成策略对比分析](https://arxiv.org/abs/2610.30157)
- 论文从 14 个评估维度对比 CLI 与 MCP：CLI 在单用户、本地工作流中效率更高，MCP 则通过结构化 JSON-RPC 提供细粒度访问控制、凭证隔离、结构化审计和多租户治理，满足 CLI 无法覆盖的需求。
- 借助 progressive disclosure 技术，MCP 消除了上下文窗口开销这一历史弱项，token 效率可与 CLI 相当，同时保留其架构优势；生产系统建议采用混合架构。
- 分析结合了 NSA 正式指南、OWASP 安全标准以及 BCG 与 Gartner 的经济模型，为 AI Agents 的 tool calling、RAG 与 multi-agent 场景下的工具集成选型提供依据。

### [游戏中的反馈反噬：LLM 玩家会重复刚看到失败的走法吗？](https://arxiv.org/abs/2610.30205)
- 研究发现在 Sokoban、Connect Four、Othello 中，把失败走法与错误信息写入 transcript 的 tool calling 记录反而让 8 个指令微调模型（135M–1.7B）更倾向重复该走法（纠正增益 G = -1.38 nats/token），且主要经由走法的表层形式起作用，对非法走法成立、对合法但致败的走法不成立，也并非每个模型都如此。
- 探索性分析显示符号由先验决定：记录之后失败走法的 log-probability 几乎不依赖其原先概率（斜率 0.18），模型本不会走的走法被抬高并进入 greedy decoding，本将走的走法被压低但仍有 38% 被重复；省略走法字符串的失败描述可保留模型原有偏好，而 'do not repeat' 指令无效、clean retry 是最差 harness、decoder ban 只能阻止完全重复而非非法落子。
- 在 OLMo 2 1B 后训练阶梯上该反转在 base 模型即存在、到 DPO 阶段基本消除；RAGEN 默认模型在自身 Sokoban 格式中、任何 RL 之前就已反转。所有测量在免费 Colab GPU 上以 float32 完成，并先复现了原论文数值，涉及 multi-agent 与 RAG 场景下的 tool calling 反馈设计。
