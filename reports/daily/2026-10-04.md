## Research and engineering

### [Oversight Has Capacity: 让 Agent Guards 适配主观且会疲劳的人类监督者](https://arxiv.org/abs/2606.08919)
- 论文探讨 agent 监督的人因瓶颈：人类监督者的注意力有限且会疲劳，因此 Agent Guards 的校准应纳入主观、随时间衰减的监督容量，而非假设恒定满负荷审核。
- 对 multi-agent 与 tool calling 系统而言，这意味着在 MCP、RAG 等工具链中需动态调节拦截、升级与自动执行阈值，把有限的人类审核预算优先分配给高风险或高不确定性的动作。
- 核心启示是监督是一种可耗尽的资源，guard 策略应显式建模人类疲劳与主观判断差异，从而在安全性与可运维性之间取得更实际的平衡。

### [Pi-based coding agent with hard budget caps](https://kimchi.dev/)
- 该帖子介绍了一个基于 Pi 的 coding agent，强调对 API 调用设置 hard budget caps，避免成本失控。
- 社区讨论可能涉及它与 MCP、RAG、tool calling、multi-agent 等现有 AI 工程范式的集成方式和取舍。
- 由于 HN 上 points 与 comments 很少，该话题尚属早期，但预算上限对生产级 agent 部署具有实用价值。

### [让你的 AI agent 感知周围正在发生的事情](https://github.com/SyncSo-Inc/syncso)
- SyncSo 通过 MCP 为 AI agent 提供对用户环境上下文的实时感知能力。
- 结合 RAG 与 tool calling，agent 可以主动检索并调用外部信息源完成任务。
- multi-agent 场景下可共享周边事件感知，提升协作与响应的一致性。

### [Show HN: AgentiLoop Agent Mac GUI Agent Loop for macOS 14.6 or Later](https://agentiloop.ai/)
- AgentiLoop 为 macOS 14.6 及以上提供 Mac GUI Agent Loop，Auto-Pilot 接受目标后以 Cycle 形式持续运行，直至目标达成，并配有 Stop All 等 kill switch 控制。
- 路线图包括 multi-agent 场景：11 月将支持同一项目上多个 Auto-Pilot 并行，且 Auto-Pilot tab 可自动派生其他 tab，体现更复杂的 tool calling 与 RAG 工作流潜力。
- 团队正用 GoDot 4 开发类 Mario Kart 克隆 GoKart，已累计超过 20 小时的开发记录，用于验证 Agent 在真实项目中的长期循环执行能力。
