### [Doing Less with More: 代理计算适用性的第一性原理探索](https://arxiv.org/abs/2610.23921)
- 论文通过受控算术任务比较七种方法：原生 function calling、REST、SOAP、MCP 微服务、直接 LLM 响应、本地 Ollama 模型以及由本地 LLM 调用 MCP 工具的 agentic 系统，并强调需保留运算符优先级语义。
- 确定性方法达到 100% 准确率且延迟可忽略；直接 LLM 评估最高仅 92.9% 准确率但延迟超过原生 function call 的 22,000 倍，而最佳 MCP tool calling agent 达 99.9% 准确率却带来近 1,000,000 倍基线延迟。
- 结果说明 LLM 方案不适合精确算术，并据此提出基于准确率与吞吐需求选择架构的决策框架（ADF），建议按任务类型探索多种架构，而非采用 LLM 或 multi-agent 的 one-size-fits-all 方案。

### [Unified Multiparadigm Fusion Intelligence for Rare Disease Diagnosis](https://arxiv.org/abs/2610.24024)
- FusionRare 提出统一多范式融合框架，整合知识驱动的符号推理、深度学习模式识别、基于病例的患者检索与 LLM 启发式推理，并通过统计元聚合与知识增强的 agentic reflection、multi-agent 协作机制缓解单一范式的结构性局限。
- 在 2,528 例严格隔离的临床病例上，FusionRare 实现最先进的罕见病优先级排序：仅表型诊断的宏平均 Recall@1 达 51%，表型-基因型联合分析达 79%，在严格防泄漏协议下优于 DeepRare、GPT 5.5 等前沿 LLM 以及 PhenoBrain、LIRICAL 等专用工具。
- 随机交叉的临床医生-AI 验证显示，FusionRare 在 45% 的决策中提升真实诊断排名、改善 62% 的医生信心并将诊断时间缩短 21%，表明多范式协同可弥合计算基准与临床可用可靠性之间的差距，并为高风险、医疗资源匮乏场景中的可信诊断 AI 部署提供可复现框架。

### [World of SWECraft：通过模拟软件世界实现规模化 Agent 协作](https://arxiv.org/abs/2610.24061)
- 提出 Software World 框架，用真实、相互依赖的 Python 包构建模拟软件世界，让 multi-agent 在仿真生态中自主发现任务并协作维护包、提升软件效率。
- 在三个世界中运行超过 10,000 小时 agent 工作、覆盖八个模型，发现性能提升随 inference-time compute 扩展，最佳模型将隐藏依赖包的下游效率提升至 31%。
- 通过变化 communication、ownership 与 resource allocation 研究协作要素；多数 agent 能借协作找到有意义任务，但部分前沿模型会过早停止寻找改进，框架与 traces 已开源。

### [Scaling in Games: Continued Pre-Training For Embodied Agents In Diverse Virtual Worlds](https://arxiv.org/abs/2610.28698)
- 该研究通过 120 种训练配置（0.8B 至 27B 的四档模型规模、50 至 1,600 小时的六档数据预算、从仅 Minecraft 到多世界混合的 5 种数据混合方式）系统考察 CPT 在数据量、多样性与模型规模三个轴上的缩放规律，并用三级验证损失与游戏基准评估在语料内世界和相关/遥远未见世界上的性能与泛化。
- 结果显示：数据量提升语料内表现，多样性促进向相关世界的迁移但对遥远世界增益有限；单世界训练下模型规模提升数据效率却对遥远世界泛化更差；训练呈现早期以跨世界广泛收益为特征的 interface 阶段和后期收益收窄至语料内与相关世界的 world 阶段，并拟合出验证损失与数据量、多样性、模型规模的经验缩放律。
- 模型在 3D 世界中与 Minecraft 专家模型及前沿模型相比具竞争力，并在实时场景表现最佳；但模仿学习的局限与遥远世界的持续差距表明，构建通用具身智能体需要超越 continued pre-training 的更强训练阶段（如引入 MCP、RAG、tool calling 或 multi-agent 等机制）。

### [打招呼的代价：AI Agent 通信协议握手开销的实证研究](https://arxiv.org/abs/2610.30151)
- 首个按阶段分解的握手基准：在 50ms RTT 下，legacy MCP 握手需 3 次往返、230ms，A2A 仅需 1 次往返、61.0ms，说明往返次数主导握手成本。
- 当 LLM 读取对端元数据时，握手成本随能力清单规模增长（每项能力 24-107 tokens），200 项能力的对端会占用 200k 上下文窗口的 11%。
- MCP 2026 修订将握手从 3 次往返降至 2 次，并借助 era pinning 在热重连时降至 0 次，印证了所测成本；全套 harness、原始数据与分析已开源。

### [MCP 与 CLI：AI Agents 工具集成策略对比分析](https://arxiv.org/abs/2610.30157)
- 论文从 14 个评估维度对比 CLI 与 MCP：CLI 在单用户、本地工作流中效率更高，MCP 则通过结构化 JSON-RPC 提供细粒度访问控制、凭证隔离、结构化审计和多租户治理，满足 CLI 无法覆盖的需求。
- 借助 progressive disclosure 技术，MCP 消除了上下文窗口开销这一历史弱项，token 效率可与 CLI 相当，同时保留其架构优势；生产系统建议采用混合架构。
- 分析结合了 NSA 正式指南、OWASP 安全标准以及 BCG 与 Gartner 的经济模型，为 AI Agents 的 tool calling、RAG 与 multi-agent 场景下的工具集成选型提供依据。

### [游戏中的反馈反噬：LLM 玩家会重复刚看到失败的走法吗？](https://arxiv.org/abs/2610.30205)
- 研究发现在 Sokoban、Connect Four、Othello 中，把失败走法与错误信息写入 transcript 的 tool calling 记录反而让 8 个指令微调模型（135M–1.7B）更倾向重复该走法（纠正增益 G = -1.38 nats/token），且主要经由走法的表层形式起作用，对非法走法成立、对合法但致败的走法不成立，也并非每个模型都如此。
- 探索性分析显示符号由先验决定：记录之后失败走法的 log-probability 几乎不依赖其原先概率（斜率 0.18），模型本不会走的走法被抬高并进入 greedy decoding，本将走的走法被压低但仍有 38% 被重复；省略走法字符串的失败描述可保留模型原有偏好，而 'do not repeat' 指令无效、clean retry 是最差 harness、decoder ban 只能阻止完全重复而非非法落子。
- 在 OLMo 2 1B 后训练阶梯上该反转在 base 模型即存在、到 DPO 阶段基本消除；RAGEN 默认模型在自身 Sokoban 格式中、任何 RL 之前就已反转。所有测量在免费 Colab GPU 上以 float32 完成，并先复现了原论文数值，涉及 multi-agent 与 RAG 场景下的 tool calling 反馈设计。
